You can always leave BioKids; nothing locks you in. How to remove it depends on how you installed it.

{% call m.callout('tip', 'Only want a break for a while?') %}

No need to remove anything. In the panel, under Children → Time rules, untick "Let BioKids manage this child" (your family passphrase is asked). Tick it again and everything carries on where it left off.

{% endcall %}

First: your family's backup (optional)

If you might install it again one day, use Settings → Back up and move → Download the backup in the panel to save the children's rules and history as one file, and copy it to a USB stick. The file is sealed with your family passphrase; it holds no PINs and no mail settings.

Remove BioKids, keep Debian

Even when installed from the ISO, BioKids sits on top of Debian as packages. Remove them and a plain Debian with the Xfce desktop is left. Sign in with your own account and open a terminal:

    {% call m.step('Delete the assistant\'s models (if installed)', 'assistant') %}

    This deletes Ask Me's models, several GB of them.

    {{ m.code('sudo apt purge biokids-ai') }} {% endcall %} {% call m.step('Remove BioKids', 'remove') %} {{ m.code('sudo apt purge biokids biokids-desktop biokids-core biokids-daemon biokids-panel biokids-shell biokids-voice') }}

    It asks one question: "Delete the stored BioKids data for this family?" The default answer is No, and the records stay on the computer. Answer Yes to delete everything: the rules, the history, the voice recordings and the downloaded natural voice.

    This also brings back Debian's usual boot menu.

    {% endcall %} {% call m.step('Delete the children\'s accounts (if you want)', 'accounts') %}

    The children's accounts on the computer, and their files (their drawings, for example), are left on purpose. To delete them, once for each child, with their username:

    {{ m.code('sudo deluser --remove-home elif') }} {% endcall %} {% call m.step('Clean up what is left', 'clean-up') %} {{ m.code('sudo apt autoremove') }}

    If you turned on phone access, Tailscale was installed as well; remove it with sudo apt purge tailscale if you no longer need it.

    {% endcall %}

Go back to Windows only

If the computer has both Windows and BioKids, you can delete BioKids' partitions and give the space back to Windows. These are Windows' own tools, not BioKids'; do it carefully and in order.

{% call m.callout('danger', 'Before you start') %}
  • Back up your important files.
  • If you use BitLocker, have your recovery key at hand (aka.ms/myrecoverykey).
  • Keep the order: first make Windows start first and check it, then delete the partitions. The other way round, the computer may not start.
{% endcall %}
    {% call m.step('Start Windows', 'win-start') %}

    Choose Windows Boot Manager in the boot menu.

    {% endcall %} {% call m.step('Make Windows start first', 'win-first') %}

    Type cmd in Start, right-click Command Prompt, choose Run as administrator and type:

    {{ m.code('bcdedit /set {fwbootmgr} displayorder {bootmgr} /addfirst', 'Command Prompt (administrator)') }}

    Restart: Windows should start directly, without the menu. If it does not, stop here and move Windows Boot Manager to the top of the Boot Order in the computer's settings (BIOS/UEFI).

    {% call m.callout('note', 'Legacy (BIOS) installs') %}

    If Windows' BIOS Mode is "Legacy", instead of this command go to Settings → System → Recovery → Advanced startup → Troubleshoot → Advanced options → Command Prompt, type bootrec /fixmbr, then restart and check that Windows starts directly.

    {% endcall %} {% endcall %} {% call m.step('Delete BioKids\' partitions', 'delete-partitions') %}

    Right-click the Start button and open Disk Management. BioKids' partitions have no drive letter; recognise them by size: one as large as the space you freed for BioKids, and a smaller swap partition of a few GB next to it. Right-click each and choose Delete Volume.

    {% call m.illus('Delete only the red ones. Do not touch EFI, C: or Recovery.') %}

    {% endcall %} {% call m.callout('warn') %}

    Never delete the EFI System Partition, the Recovery partition or C:. If you are not sure which is which, stop and write to us.

    {% endcall %} {% endcall %} {% call m.step('Grow C:', 'extend') %}

    Right-click C: → Extend Volume… → Next → Finish. The free space joins C:.

    If Windows greys this option out, the free space is not right next to C: (a Recovery partition may sit between them). Then right-click the free space and use New Simple Volume to make it a separate drive (D:).

    {% endcall %} {% call m.step('Remove the debian folder from EFI (optional)', 'efi-clean') %}

    So that an unused "debian" entry does not linger in the firmware's boot list, type these one by one in an administrator Command Prompt. Type the letters carefully.

    {{ m.code('mountvol S: /s rd /s /q S:\\EFI\\debian mountvol S: /d', 'Command Prompt (administrator)') }} {% endcall %}

If BioKids is the only system

Two ways: go back to a plain Debian with the package steps above, or install another system (Windows, for example) from its own USB stick. Its installer erases the disk, so take your family's backup and your files first.

Something wrong?

After deleting, a black screen says "grub rescue"

The computer is still looking for BioKids' boot loader. Open the computer's settings (often {{ m.kbd('F2') }}, {{ m.kbd('F10') }} or {{ m.kbd('Del') }}) and move Windows Boot Manager to the top of the Boot Order. On a Legacy (BIOS) install, run bootrec /fixmbr from Windows' recovery environment.

What happens to my family's data?

It stays on the computer unless you choose to delete it. Answer Yes to the question asked while removing, and the rules, history and records are deleted. If you deleted the partitions, it is all gone anyway.

Can I install it again later?

Of course. After installing, load your backup with Back up and move → Restore in the panel, and the children's rules and history come back.
